# ClashLegendsWebsite 开发说明

版本：2026-10-20。用途：交给用户自己在 Codex 中打开的 ClashLegendsWebsite 项目进行开发。本文是开发需求与建议，不是已经完成的网站，也不是已经验证全部游戏内容的百科。

## 1. 已确认的目标与边界

- 这是个人制作的 ClashLegends 游戏宣传与介绍网站，与求职、简历或招聘无关。主体是游戏，不是作者技术能力展示。
- 提供游戏总览、玩法介绍、卡牌与单位详细介绍。支持完整简体中文与英文切换。
- 视觉要求：现代、简洁、美观、有游戏辨识度。作者主要看最终网页，不承担框架、组件库或模板选择工作。
- 用户已经新建 Codex 项目 ClashLegendsWebsite。本说明不授权其他助手另建或启动 Work/Codex 任务。
- 用户直接打开网站验收，不需要截图报告或逐张截图审批。开发者须自行做浏览器与交互检查。
- 最终部署目标是 Sites。开发与部署分开：本轮先做可打开的本地网站，准备部署交接；未确认发布范围前，不擅自公开。若本地访问不了，再说明可用的私有部署方案，不把远程生产部署冒充本地预览。

## 2. 推荐执行路线

采用真实游戏素材、定制视觉、统一内容模板的静态网站。不套完整 SaaS 营销模板，不先建后台。

设计指导首选 Anthropic 官方 frontend-design：
https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md
该技能目录许可证为 Apache-2.0，引用或复制时保留适用许可。它是设计指导，不保证自动产出优秀设计，也不代表本项目已经安装。

可选审查指导：Vercel web-design-guidelines：
https://github.com/vercel-labs/agent-skills/blob/main/skills/web-design-guidelines/SKILL.md
仓库声明 MIT。用于可用性、无障碍、国际化与交互审查，不是视觉模板；读取它引用的最新规范，将工具名适配为实际可用工具，不盲跑安装命令。

上述为已核实官方来源，不声称“全网最推荐”。如果当前环境无法加载 skill，直接遵守本文的具体设计要求继续开发，不把安装 skill 变成阻塞项。无需同时安装多个 UI skill 或购买模板。

技术默认：静态 HTML/CSS/JavaScript；若项目已经有合理框架则沿用。多个图鉴详情页应从统一数据和模板生成，必要时使用一个小型构建脚本，不复制维护几十份 HTML。避免为此引入服务端、数据库、登录、CMS、复杂插件体系。最终输出标准静态文件，入口与路由须按实际 Sites 托管规范检查。不要为迁就“无构建”而牺牲内容复用，也不要为几十个页面引入重量级全栈架构。

## 4. 页面与用户路径

### 首页
目标：30 秒内知道这是什么游戏，并想继续看。
- 导航：ClashLegends、游戏总览、图鉴、机制、更新、中文/EN。
- 首屏：有辨识度的真实游戏主视觉、醒目标题、两行以内介绍；主要动作是“探索图鉴”，次要动作是“了解玩法”。有真实视频时再增加播放入口。
- 核心特色：围绕实际战斗、熟悉的角色和独特卡牌机制，三项即可，拒绝空洞营销词。
- 代表卡牌：精选 4–6 张，覆盖不同玩法，不用全量图鉴占满首页。
- 实机展示：有素材则展示，没有则用真实卡面组成精致编辑式构图，不伪造游戏画面。
- 最近更新：仅使用明确发布/记录的内容，不把工作区变更当正式更新公告。
- 页脚：关于、GitHub、素材说明、非官方项目声明；社交链接只放核实过的目标。

### 游戏总览 / 玩法
用玩家语言解释胜利条件、战场、卡组、资源、部署、技能与对局节奏。重要数字均从当前规则核对。用少量图示与短段落，不直接堆工程文档；不描述 ECS、沙箱、AI 开发过程和性能调试史。

### 图鉴列表
- 默认显示可选卡牌；分类仅使用实际存在的类别。
- 支持中英文名称搜索、费用与类型筛选、清除条件、无结果提示。
- 如展示“全部单位”，将可选卡牌与派生形态/召唤物明确区分。
- 搜索忽略英文大小写，支持已记录的中英文别名；不必首版实现拼音/模糊搜索系统。
- 卡片显示卡面、名称、费用、简短定位，统一比例，不强行裁掉头部或技能关键部位。
- 详情有独立 URL，浏览器前进/后退、刷新、直接访问均有效。

### 卡牌 / 单位详情
- 名称、定位、主图、费用与部署信息。
- 基础属性：只列适用字段；攻击间隔与攻击速度不能混淆，时间/距离/百分比写清单位，缺失值不能写成 0。
- 技能：图标、名称、一句话效果、触发条件、详细数值与必要例外。
- 多形态和召唤物：通过同页分区或关联链接表达，不让玩家误以为都是独立可选卡。
- 机制标签链接到统一词条；普通介绍不塞入所有边界条件。
- 数据版本说明。没有版本号可用时使用源提交短 SHA 与核对日期，不杜撰语义版本。

### 机制说明
第一版只覆盖图鉴实际引用的核心机制，如控制、护盾、不可选中、变形、死亡与复生。每个词条：简短定义、玩家可见效果、必要例外。以当前实现为准，不靠记忆补齐。

### 更新与关于
- 更新页内容少也可以，真实而简短；没有可信条目时可暂不在导航展示。
- 关于页讲个人兴趣项目与创作动机，不写招聘、自我评价或技能履历。
- 非官方与素材归属说明不能冒充授权证明。公开前核对拟公开素材与适用政策；不自动上传完整原版音频、模型或素材包。

## 5. 设计约束：不只写“现代美观”

推荐方向：深色、清爽、偏编辑式游戏展示。主色使用深炭/墨蓝，正文柔白，一种青蓝强调色，暖金仅作小面积点缀。禁止大面积渐变、满屏发光边框、夸张玻璃面板和通用 SaaS 三列功能卡拼贴。

- 一个主视觉焦点：真实战场或精选角色构图，而不是多个竞争的大标题。
- 宽屏内容区约 1120–1280px；边距与间距使用统一节奏；移动端保留呼吸感。
- 中文与英文分别调字号、行高和标题断行。优先清晰字体及可靠本地回退，不为字体下载带来巨量包体。
- 正文建议至少 16px，卡面标题清晰，数据布局规整。不把所有文本缩小来塞进卡片。
- 动效用于悬停、展开、导航反馈，短而克制；尊重 prefers-reduced-motion。不使用强制滚动、鼠标跟随或自动播放声音。
- 实际页面好看优先，不追求每屏都“有动画”。
- 不借原版 LoL 官网整页复制设计，也不用素材归属声明代替授权。

## 6. 双语要求

- 中文和英文是同一套内容模型的两个本地化版本，不复制两份互不关联的站点。
- UI、标题、技能说明、机制、空状态、按钮、图片替代文本、SEO 标题和描述均支持双语。
- 数值和关联 ID 共用，不能两种语言各填一套数值。
- 游戏专有名称有固定译名表；官方角色英文名可核实使用，自创技能译名标记为本项目译名，不声称官方译名。
- 不在用户浏览时调用 LLM 翻译；所有内容预先生成并核对。
- 推荐 /zh/ 与 /en/ 成对静态页面。切换语言留在同一实体页面；查询条件尽量保留。
- URL 的语言优先于本地偏好。根页面首次可按浏览器语言选择，用户手动选择后记住偏好，不强制跳离用户打开的语言链接。
- 设置 html lang、双语 hreflang、正确 canonical；未公开前不编造生产域名，正式发布时补齐。
- 英文翻译缺失在内容检查中报错；原型期可以有明确的待补提示，首版交付不能大片中英混杂。

## 7. 最小内容模型（按实际需要落地）

卡牌 Card：稳定 id、名称 zh/en、类型、费用、部署结果 unitIds、卡面、简短介绍、是否当前可选、来源。
单位 Unit：稳定 id、名称 zh/en、属性、技能、形态关系、召唤物关系、机制引用、展示图片、来源。
技能 Ability：id、名称/说明 zh/en、图标、条件、共享数值、机制引用；只在复用有意义时独立，不强制每个技能建立复杂注册层。
机制 Mechanic：id、双语定义、可选例外说明。
元数据：sourceCommit、checkedAt、内容状态；媒体记录路径、用途、来源与是否允许公开的待核查状态。

这些是概念模型，不强制拆成四套大型类层次。使用简单 JSON/模块即可。公共页面绝不暴露本机绝对路径、私人记录和内部调试信息。

## 8. 工程与素材管理

建议保持少量目录：内容数据、模板/页面、样式、交互脚本、精选媒体、检查工具、简短说明。采用一套详情模板；不要为每个英雄手写一份页面组件。

- 网站只带用到的卡面、技能图标与宣传媒体。禁止复制整个 Godot 工程、.godot、导入缓存、原始音频、所有 glb 和开发素材库。
- 不默认下载整个巨大仓库及 LFS 内容；通过连接器或已提供的只读源逐项读取必要文件。
- 图片使用适当尺寸与压缩格式，保留必要透明通道；列表图懒加载，首屏主要视觉不延迟到看不见。
- 视频有封面、点击播放与加载控制，不自动下载多个大视频。
- 不做实时 3D 模型预览、用户系统、评论、卡组模拟器、战绩、联网对战或自动抓取后台。
- 不引入第三方分析追踪、Cookie 弹窗服务或远程 AI API。
- 所有展示内容按快照生成；更新游戏后重新核对并生成网站，不要求网站启动游戏引擎。

## 9. 实施顺序与自主性

1. 检查 ClashLegendsWebsite 现有结构与说明，保留用户文件；记录源仓库版本。
2. 读取上述最小入口，形成卡牌/派生实体清单和素材清单。不要先阅读全部 archive/issues/deliveries。
3. 做好首页、图鉴列表和三个代表性详情：普通单位、复杂形态/召唤单位、法术。优先选实际素材完整的条目。
4. 在浏览器中自查中文/英文和手机/桌面布局，自己修复明显的比例、排版、交互问题；不要求用户逐屏审核。
5. 复用模板补齐当前可选卡牌与必要派生实体，再完善机制与总览。不能拿三个样例冒充完整网站。
6. 做内容、链接、双语与交互检查；提供可打开的预览地址、覆盖说明和真实缺项。
7. 准备 Sites 部署材料；发布动作另按用户确认的范围进行。

开发者自主选择常规实现细节，不把配色、组件或目录命名逐项反问用户。只有缺少必须素材、内容冲突无法核实、需要新增权限或发布决定时，提出一个明确问题；其他部分继续做。

## 10. 验收：直接打开网页

用户不审查截图。最终交付应给出实际可访问的预览入口，并说清在哪里打开；本机 localhost 不能让手机直接访问，不能把它当跨设备地址。需要远程链接时，确认发布范围并使用支持的部署流程。

开发者自行检查：
- 首页/总览/列表/详情在 390px 和 1440px 左右宽度正常，320px 不出现横向溢出。
- 中英文切换、刷新保持语言、详情页直达、前进后退、搜索、筛选、无结果和清除功能均工作。
- 菜单和弹层可用键盘操作，焦点可见，Escape 行为合理，图片有适当替代文本。
- 页面无破图、空按钮、占位链接、控制台报错与未处理异常。
- 内容检查覆盖重复 ID、断裂引用、缺失翻译、缺图、错误数值类型和无依据的下载链接。
- 显示可选卡牌数量时有配置依据，派生实体不混入计数。
- 英文长标题不挤破布局，中文没有不自然的巨大字距或孤行。
- 列表不预载全部原始图片/视频；若测性能，报告测量条件，不编造 Lighthouse 分数。
- 开发测试保持轻量，不为展示站启动游戏重压力测试。

用户最终只需判断：视觉是否满意、游戏介绍是否准确、查单位是否方便。交付说明应短，不能用长篇“全部完美”的自评替代可打开网站。

## 11. Sites 交接

当前目标为本地开发、部署就绪，非自动公开。

实际发布时读取当前 Sites 指引：
- 如已有 .openai/hosting.json，读取真实 project_id 并复用，不能重复建站或编造 ID。
- 发布需要匹配的源码提交与构建产物；先同步精确源码状态，再保存版本，再部署该版本。
- 静态归档包含实际托管配置和生成站点文件，而不是把整个源游戏项目打包。
- 新站默认私有；面向所有玩家的公开访问是单独的受众决定，不能把私有部署称作公开官网。
- 所有部署 URL 都是部署，不是本地预览。检查最终部署状态、详情直链、语言路由和访问权限。
- Codex 当前会话没有 Sites 能力时，交付站点源码、构建输出和部署步骤；不要编造成功链接或让用户找不存在的按钮。

## 12. 开发完成时的简短汇报格式

1. 打开地址及访问方式。
2. 已完成页面和中英文覆盖情况。
3. 使用的游戏源提交、核实的可选卡牌/派生实体数量。
4. 必须补齐的素材或无法核实的内容（没有则说明没有）。
5. Sites 发布准备状态；未发布就明确写未发布。

不要提交截图包作为验收材料，不自动联系第三方，不更改游戏项目，不创建新的 Work/Codex 任务。

## 附录 A：本轮实际读到的内容样本与设计影响

### A1. 不能做成只有被动单位的普通 CR 图鉴

镜像法术文档确认：八张卡牌洗牌、备战前两个主动席、全场最多两个可操作技能槽；主动技能有费用、次数、冷却或强化方式。网站应介绍“部署卡牌 + 主动技能”的特色，卡牌详情必须能表达主动席与非主动席差别。

来源：

### A2. 竞技场内容可以直接从当前手册开始

arena.md 写明正常比赛 185 秒、加时 120 秒，起始金币 5、上限 10，基础每 2.8 秒回复 1 金币；首波小兵在开场 5 秒。正式地图为晴昼峡谷 3D 场景。由此首页不应只讲“两边下牌”，还应突出兵线、资源节奏与场景。

网页对外无需复制所有坐标、设计分辨率和桥宽；这些是工程描述，不是玩家总览重点。胜负规则仍须继续读比赛状态实现，不能仅凭本页自行推断加时和平局处理。

### A3. 冰鸟适合作为复杂详情模板样例

anivia.md 写明：5 费、生命 620、基础普攻 78、攻击间隔 1.7 秒、地空目标；一格 40 游戏单位。首次被击败生成 165 生命的蛋，存活 3 秒后满血复生，复生后不再生蛋。已落地风暴不会因冰鸟死亡消失。

页面应把冰鸟与蛋放在同一阅读路径中；蛋标为派生形态，不给它虚构部署费用。技能“冰雪风暴”要区分部署费用与技能费用（文档中技能费用为 2）。数值区优先展示少量核心属性，质量、发现范围等可放详细区域，不让首屏变成配置转储。

### A4. 镜像证明“费用”不能只有一个必填数字

镜像费用取上一张卡实际部署形态的基础费用，不能简单写固定值；卡片允许显示“随目标 / Varies”。初始没有复制目标时，与未翻译、缺失数据不是同一状态。详情介绍复制的是完整定义而非场上残血状态；高级规则可折叠，不将网络请求确认细节搬上宣传页。

真实卡面引用：assets/cards/mirror_loading.png；原画来源记录 assets/cards/mirror_source.md。技能图标可能为 DDS，需要制作网站可显示的衍生格式，不能将浏览器不支持的格式直接作为图片使用。
